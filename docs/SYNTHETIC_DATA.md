# Synthetic data: what it is and what it is not

> **Everything in `backend/data/synthetic/` is fabricated.** It was generated by
> `terrapulse.data.synthetic` to exercise the software, and it does not come from any satellite
> observation, landslide inventory or measurement of the 2024 Thame GLOF (or any other event).
> Event IDs `SYN-EVT-xx` and missions "C-band-like (SYNTHETIC)" / "L-band-like (SYNTHETIC)" are invented.

## Purpose

- Test preprocessing, imputation and encoding.
- Test grouped (event-wise) splitting and cross-validation.
- Test class-imbalance handling, threshold selection and metrics.
- Produce realistic-shaped JSON for the dashboard's ML panel.

## Reproducibility

- Seed: `20240816` by default (`TERRAPULSE_SEED` env var or `generate --seed N`).
- The same seed always produces byte-identical data (tested in `tests/test_synthetic.py`).
- Each CSV has a matching `*.card.json` with the configuration, positive rate, test events and the assumption list below.

## Structure

- 8 event groups, 320–520 samples each (≈3,500 rows). Each event is a spatial cluster
  (σ ≈ 0.012°) around a random centre inside an approximate Solukhumbu bounding box.
- Whole events are assigned to `train` or `test` (2 test events, each with at least 5 positives).

## Generative assumptions

| aspect | assumption |
|---|---|
| Elevation | event base 3000–4800 m + N(0, 450 m) |
| Slope | N(28°, 11°) clipped to 0–75° |
| TWI | decreases with slope |
| Distances | log-normal (river median ≈ 600 m, road median ≈ 3 km) |
| Rainfall | cumulative by construction, event-level storm intensity |
| Soil moisture | increases with 7-day rainfall |
| NDVI | decreases with elevation |
| Land cover | derived from elevation and NDVI |
| Geology | weighted sample; moraine more common above 4300 m |
| **Label** | logistic latent model: slope bump (peak ≈ 35°) + 3-day rain + soil moisture − NDVI − log(distance to river) + geology + concavity + event random effect + noise; intercept solved for ≈ 9% positives |
| Label noise | ≈ 2% flips, more likely where `label_confidence` is low |
| **SAR change** | generated **conditional on the label**. Positives get larger \|Δσ°\|, lower coherence and larger negative LOS displacement |
| Polarisation | C-band-like rows have VV/VH only; L-band-like rows have HH/HV only (about 25%) |
| Target-derived | severity/area/displacement/change class are drawn *after* the label |

### Missingness

| column | pattern |
|---|---|
| HH/HV or VV/VH | structurally missing by sensor |
| `sar_coherence` | ≈ 10% (no interferometric pair) |
| `los_displacement_mm` | ≈ 15%, plus extra where coherence < 0.25 (unwrapping failure) |
| `ndvi` | ≈ 12% (cloud) |
| `soil_moisture` | ≈ 7% |
| `rainfall_30d_mm` | ≈ 3% |
| `distance_to_road_m` | ≈ 2% |
| DEM void | ≈ 1% of rows lose elevation/slope/aspect/curvature/TWI together |
| `land_cover` | ≈ 1% |

## Consequences for interpreting metrics

- **Detection-mode scores are inflated by construction.** The SAR features were *made* to separate the
  classes, so a high PR-AUC only shows that the pipeline can find a planted signal.
- **Forecast-mode scores reflect the chosen latent model**, not real-world predictability.
- Feature-importance rankings reproduce the generator's assumptions. **They are not scientific findings.**
